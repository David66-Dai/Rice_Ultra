# 设备权限、状态同步与通知

设备控制通过后端用户名授权名单限制；普通已登录账号可查看状态和接收通知，无法发送控制指令。
账号即使已有 `ADMIN` 角色，也必须出现在名单中，避免旧账号默认角色导致权限扩散。

在 `conf/config.yaml` 第一份文档现有 `app` 下设置：

```yaml
app:
  devices:
    control-users: [admin, danglong, dzh]
```

使用登录用户名，不使用显示名称；名单不区分大小写。空名单默认禁止所有人控制。
修改配置后重启 Java 后端生效；这不会创建账号、修改密码或打开设备。
浏览器只获取当前账号是否有权限，不获取完整名单或配置文件。

## 状态同步与冲突处理

- 登录后全局启动一个带 Bearer 令牌的 HTTP 长轮询，切换页面仍接收消息。
- `GET /api/devices/sync` 返回设备状态、当前账号权限、通知及未读数量。
  携带 `after=<cursor>&waitSeconds=25` 等待新状态，变化时立即返回。
- `POST /api/devices/control` 必须携带 `stationId`、`device`、`enabled` 和最新 `expectedRevision`。
  后端串行检查版本和发送指令，旧版本返回 HTTP 409；客户端重新同步后再由用户决定操作。
- 网络断开时禁用开关并自动重连；页面重新可见或网络恢复时重新读取完整快照。
  控制请求超时不会自动重发，避免结果不明时重复启动设备。
- 设备状态表示后端最后成功发送的控制指令。当前串口协议没有执行回执，不能据此证明继电器已动作。
  后端重启时状态为“未知”，不会自动补发开关指令；串口不可用时禁止操作。
- 当前控制服务对应单个 Java 进程和单个串口。不要让多个后端实例同时控制同一串口。

## 通知

右上角“退出登录”左侧的铃铛显示通知和未读数量，支持“全部 / 设备操作 / 病虫害识别”分类。
成功发送设备指令后，所有已登录用户收到包含操作者、动作和功能名称的通知。
携带旧版本重复提交会被拒绝。用户在同步最新版本后可以明确重新发送开启或关闭指令，
便于在缺少执行回执时再次下达停止操作；每次接受的指令都会记录并通知。
拒绝、校验失败和串口发送失败不会生成成功通知。

通知存入数据库，列表显示最近 100 条；未读数量按当前账号单独统计。
“全部已读”通过 `POST /api/notifications/read` 的 `throughId` 标记已看到的消息，
不会把该请求之后才产生的新消息误标为已读，也不影响其他账号。

病虫害识别已预留 `pest_disease` 通知类型与可信后端发送入口
`DeviceActivityService.publishPestDisease(stationId, message)`。
后续识别流程在取得真实结果后调用该入口，即可复用存储、广播、未读计数与前端分类。
当前不会产生模拟识别警报，也没有向普通客户端开放任意广播接口。

## AstrBot 接入

新版插件位于 `integrations/astrbot_plugin_agri_control`，安装包为同目录旁的 ZIP。
Java 只开放受限的 `/api/astrbot/devices/sync` 与 `/api/astrbot/devices/control`，
使用独立令牌并在服务器端把 UMO + sender ID 精确映射到平台登录用户名。
机器人传入的用户名不参与授权；每次请求都会复查账号启用状态和 `control-users`。

普通机器人开启先生成二次确认编号，确认前不发送指令；停止立即执行。
显式 `/agri_test` 可在服务器和插件双开关都开启时跳过二次确认，但不会跳过账号权限、
设备版本、串口可用性、时长限制或自动关闭。完整安装与命令说明见插件目录的 `README.md`。

首次部署需确保通知及已读表已经建立。当前开发配置的 Hibernate `ddl-auto: update`
会创建新增表；手动管理数据库结构的部署请执行
`server/sql/migrations/20260911_device_notifications.sql`。

按账号已读隔离、失败处理及前端重连/取消竞态。测试不连接实际水泵、驱虫灯或生产数据库。
